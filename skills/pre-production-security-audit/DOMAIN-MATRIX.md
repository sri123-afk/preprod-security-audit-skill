# Domain Matrix (30 Domains)

Every finding is tagged with one or more domain numbers from this matrix. Domains 1 to 14 are the original core set; 15 to 30 extend it with OWASP Top 10:2025, pipelines, supply chain, deserialization, access control, authentication, caching, business logic, client and protocol layers, cryptography, infrastructure, resilience, AI and agents, desktop and mobile, privacy, and operational readiness.

Use the matrix two ways:

- **During hunting:** the ledger's `domains` field says which rows a unit must satisfy. The attack-class files give the detailed hunt steps for each row.
- **During remediation:** the right-hand column is the required fix pattern. `REFERENCE-PATTERNS.md` has code for the most common ones.

| Domain | What to Detect (Attack Classes & Failure Modes) | Required Fix & Remediation Pattern |
| :--- | :--- | :--- |
| **1. Payment Gateways & Guest Checkout** | Client-supplied prices, discounts, currencies, or tax rates; negative quantities; fulfillment on browser redirect; payment script tampering; unsigned guest checkout URLs; webhook replay or spoofing. | Recalculate prices, taxes, and discounts server-side in integer minor units. Bind an immutable cart hash to the payment intent. Isolate payment entry in PCI-compliant iframes with CSP and SRI. Fulfill orders exclusively via HMAC-verified, timestamp-checked, idempotent server-to-server webhooks. |
| **2. Race Conditions, Lock Cycles & Concurrency** | Read-then-write (`TOCTOU`) on balances, inventory, or coupons; deadlocks from inconsistent lock ordering; single-process in-memory locks used across multi-replica deployments. | Use atomic SQL updates (`UPDATE ... WHERE stock >= :qty`), `SELECT ... FOR UPDATE` with bounded lock timeouts, optimistic version columns, and strict global lock ordering. Require `Idempotency-Key` headers on all state mutations. |
| **3. Memory, CPU, GPU & RPC Exhaustion** | Unbounded request bodies, RPC batch arrays, or pagination; catastrophic regex backtracking (`ReDoS`); deeply nested JSON/XML/GraphQL ASTs; hash-collision sorting/hashing degradation; zip/gzip decompression bombs (including compressed certs/keys); unbounded image/video/GPU workloads. | Enforce strict byte limits before reading streams, cap decompression ratios and output bytes, bound AST/JSON nesting depth, use linear-time regex engines (RE2) or input length caps, limit RPC batch sizes, and isolate heavy CPU/GPU tasks in bounded worker queues. |
| **4. Timeouts, Deadlines & Shared Service Costs** | Outbound HTTP/RPC/DB calls without timeouts; missing trace/context deadline propagation causing zombie work after client disconnect; unbounded retries causing retry storms and runaway upstream bills. | Set explicit connect, read, and overall timeouts on every I/O client. Propagate request deadlines (`ctx` / `AbortSignal`) downstream and cancel work on disconnect. Enforce quotas, circuit breakers, and exponential backoff with jitter. |
| **5. Blast Radius, Cleanup & Process Isolation** | Fatal crashes (segfaults, OOM, panics) in one request taking down the entire server; orphaned temp files, locks, or partial DB records after failure; shared worker pools allowing one tenant to starve others. | Isolate crash-prone or untrusted fatal paths (native parsers, media tools, plugins) in supervisor-managed child processes with memory ceilings and restart backoff. Guarantee deterministic `try/finally` cleanup and TTL purging. Partition queues and pools per tenant (bulkheads). |
| **6. Supply Chain, Trojans & Framework Exploits** | Malicious install hooks, obfuscated backdoors, or destructive wipers in packages; framework auth/routing bypasses (such as Next.js `x-middleware-subrequest` spoofing, exposed Server Actions, or SSR state leaks). | Pin exact dependency versions with committed lockfiles and SHA integrity hashes. Strip internal routing headers at the reverse proxy. Enforce authentication and authorization inside every data-access function and Server Action. |
| **7. Auth, JWT, Signature & Buffer Verification Bypasses** | JWT `alg: none` or RS256/HS256 key confusion; signature checks bypassed via truncated buffers, empty signatures, or non-constant-time comparison; UTF-8 vs. byte-length mismatches between WAF and parser; `/health` routes bypassing auth. | Enforce an explicit JWT algorithm allowlist and bind keys to one algorithm. Decode signatures to raw bytes, verify exact byte length, and use `hmac.compare_digest` / `crypto.timingSafeEqual`. Normalize Unicode and validate byte lengths after decoding. |
| **8. Developer Features & Expiry Edge Cases** | `DEBUG=true`, test bypass headers (`X-Test-User`), mock payment modes, or seed/reset routes active in production; token/cookie/cert expiry untested for clock skew or replay. | Fail startup (hard panic) if debug flags, mock auth, or test keys are present when running in production mode. Test token, session, and signed-URL expiry boundaries including clock skew and negative TTLs. |
| **9. Injections (DB, SSTI, HTML Templates & XSS)** | String interpolation in SQL, NoSQL (`$where`, `$gt`), LDAP, XPath, or OS commands; Server-Side Template Injection (`SSTI`) and unescaped HTML templates; CSV/formula and email header injection. | Use parameterized queries and strict scalar schema validation. Never concatenate user input into template strings prior to compilation. Use argument arrays without a shell for OS processes, and prefix formula characters (`=`, `+`, `-`, `@`) on CSV exports. |
| **10. Caching, CORS & Origin Boundaries** | Web cache poisoning via unkeyed headers; cache deception; CORS reflecting arbitrary `Origin` headers with `Access-Control-Allow-Credentials: true` or weak substring/regex origin checks. | Set `Cache-Control: no-store, private` on dynamic routes. Validate request `Origin` against an exact, parsed origin allowlist and emit `Vary: Origin`. |
| **11. HTTPS Abuse, MitM & IP Hijacking** | Plain HTTP fallback; missing HSTS; SSRF hitting cloud metadata (`169.254.169.254`) or internal VPCs via DNS rebinding; trusting spoofable `X-Forwarded-For` or `Host` headers; open redirects. | Enforce TLS 1.2/1.3 and HSTS preload. Resolve DNS once, pin the IP, and deny private/loopback/link-local/metadata IPv4 and IPv6 ranges on outbound fetches. Trust proxy headers only from verified load-balancer CIDRs. |
| **12. Mass Bot Torture & Automated Abuse** | Credential stuffing, carding, inventory hoarding, and distributed scraping bypassing per-IP limits via proxy rotation. | Layer rate limits across IP, session, device fingerprint, and payment BIN. Gate high-cost mutations behind proof-of-work or adaptive challenges, and deduct inventory only upon payment authorization. |
| **13. AI / LLM Core Guardrails** | Direct prompt injection; LLM output passed to shell, SQL, or HTML without sanitization; system prompt leakage; unbounded token generation exhausting GPU budgets. | Separate untrusted data from system instructions. Validate all model outputs and tool arguments against strict schemas, require human approval for high-impact actions, and enforce hard `max_tokens` and per-user cost caps. |
| **14. Data Isolation, Privacy Consent & Licenses** | Missing `tenant_id` predicates; collecting or sending PII to third parties before user consent; incompatible copyleft (GPL/AGPL) or unlicensed dependencies in proprietary builds. | Enforce tenant scoping via RLS or mandatory ORM helpers. Gate non-essential cookies, telemetry, and PII processing behind verified consent. Audit dependency licenses in CI against an SPDX allowlist. |
| **15. OWASP Top 10:2025 Crosswalk (A01-A10)** | Unmapped findings; **A10 Mishandling of Exceptional Conditions** (catch blocks swallowing errors and continuing, auth checks returning allow on exception/timeout, partial transaction commits, unhandled rejections, stack-trace leaks); **A09 Logging & Alerting Failures** (silent auth failures, privilege changes, payment anomalies, or webhook signature failures). | Map every finding to `A01`-`A10`. **A10 Fix:** Fail closed on all exceptions/timeouts, route errors through a central handler using typed errors, wrap multi-step writes in rollback-safe transactions, and return generic client errors with a correlation ID. **A09 Fix:** Emit structured security events with alert thresholds and write to a tamper-evident audit log. |
| **16. | **17. Dependency & Install-Time Defense** | `preinstall`/`postinstall`/`prepare` lifecycle scripts running on install; brand-new releases pulled automatically; typosquats, dependency confusion, or maintainer-transfer hijacks; credential harvesting from dev machines/CI (`.npmrc`, `~/.aws`, SSH keys, env vars); unvetted IDE extensions, MCP servers, or AI plugins; missing SBOMs. | Default to `--ignore-scripts` with a minimal allowlist; enforce a minimum release age policy (e.g., 7 days) plus committed lockfiles (`npm ci`, `pip --require-hashes`, `cargo --locked`); bind private scopes to an internal registry; use short-lived credentials and CI egress allowlists (rotate all secrets immediately if a compromised version is installed); pin/allowlist editor extensions and MCP servers; generate and diff an SBOM on every release. |

| **19. Access Control Depth (A01)** | `BOLA`/`IDOR` in path, query, body, header, or GraphQL args; `BFLA` (admin/internal routes reachable by regular roles or via HTTP method tampering); `BOPLA` (exposing or accepting unauthorized fields); missing `tenant_id` in joins, jobs, caches, search indexes, storage paths, or exports; client-only auth or stale JWT role claims; predictable IDs or unsigned URLs; GraphQL introspection enabled, missing depth/cost limits, alias/batch brute-forcing, or missing per-field auth. | Enforce ownership and tenant checks in the data layer on every query; default-deny in a central policy engine with role-per-route test matrices; filter inputs and outputs through role-scoped DTOs; enforce RLS or mandatory tenant-scoping helpers with cross-tenant tests; use short JWT TTLs with revocation checks; bind expiring signed URLs to user and object IDs; disable production GraphQL introspection and enforce query depth, cost, batch limits, persisted queries, and field-level auth. |
| **20. ## Gotchas

- **Trusting provenance attestations without auditing the workflow:** Supply-chain provenance proves where an artifact was built, not that the workflow was free of `pull_request_target` injection or cache poisoning. Always audit `.github/workflows/` directly.
- **Swallowing errors in auth or policy middleware (A10 Fail-Open):** A `try / catch` block that logs an error and calls `next()` turns any downstream database timeout into an authentication bypass. Always explicitly return `403`/`500` inside `catch` blocks on security paths.
- **Checking signatures after UTF-8 string conversion:** Converting binary signatures to UTF-8 strings before comparison can truncate at null bytes or drop invalid sequences. Decode hex/base64 directly to raw byte buffers and use constant-time comparison.
- **Caching responses that depend on headers not listed in `Vary`:** If a route reads `Authorization`, `Cookie`, `X-Tenant-Id`, or `Accept-Language` without setting `Cache-Control: private, no-store` or matching `Vary` headers, CDNs will serve one user's data to another.- **Middleware as the only gate:** Several middleware and proxy bypass advisories exist across Next.js versions. A matcher that misses data routes, prefetch requests, or locale variants silently removes the check. Put authorization in the data layer and every action, and use middleware only for optimistic redirects.
- **Session state on pooled database connections:** In transaction-mode pooling, `SET app.tenant_id = ...` can persist on a connection used by the next client or vanish mid-request. Use `set_config(name, value, true)` inside an explicit transaction so the value is transaction-local.
- **HTTP database drivers have no interactive session:** With an HTTP query function each call is a separate transaction, so a `SELECT ... FOR UPDATE` in one call does not protect an `UPDATE` in the next. Use a single atomic statement or a pooled WebSocket transaction.
- **Wildcards on shared platform domains:** Allowing `*.vercel.app`, `*.onrender.com`, or `*.azurewebsites.net` in CORS, redirect URIs, or CSP lets any tenant of that platform host an attacker page that passes the check. List exact hostnames.
- **Module-scope state in serverless and concurrent runtimes:** A variable assigned from request data at module level can be read by a concurrent or later request on the same instance. Keep request data in function scope.
- **Webhook signatures over parsed JSON:** Re-serialized JSON rarely matches the signed bytes, so teams "fix" it by disabling verification. Read the raw body, verify, then parse.
- **In-memory protections behind multiple instances:** Rate limits, locks, and sessions held in process memory do not span replicas or zero-downtime deploys. Use a shared store or the database.
- **`timingSafeEqual` throws on unequal lengths:** A handler that does not check length first throws, and a catch-all that continues turns the exception into a bypass. Check length, then compare, and fail closed.
- **Client-side secrets in "public" environment variables:** `NEXT_PUBLIC_`, `VITE_`, `EXPO_PUBLIC_`, and `--dart-define` values are compiled into the shipped bundle or binary. Anything secret belongs on the server.
- **Preview environments with production data:** Database branches and preview deployments copied from production carry personal data into a lower-trust environment. Use anonymized data and separate credentials.
- **Treating attestation, root detection, and biometrics as authorization:** They are signals about the device. The server must still verify identity, entitlement, and price.
- **Free-tier spin-down and cold starts on webhook receivers:** Providers time out and retry; a slow first request can cause duplicate or missed events. Acknowledge fast, process asynchronously, deduplicate by event id.
- **Rate limiting on spoofable identifiers:** Limits keyed on `X-Forwarded-For` or other client-controlled headers are bypassed by sending a new value per request. Key on verified client identity and layer account, device, and payment-instrument limits.
- **Fixing the symptom in one route:** After fixing a bypass, search for every sibling route, method, content type, and version that reaches the same resource. Add one test per variant.
